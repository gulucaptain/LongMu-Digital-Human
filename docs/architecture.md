# LongMu 文件架构

LongMu 是业务层，DiffSynth 是推理引擎。`cli.py` 解析命令，`workflow.py` 控制阶段与跨环境子进程；`stages/` 处理创作步骤，`backends/` 封装模型加载和兼容修复，`media/` 管理媒体与字幕。

配置分为部署 TOML 与项目 JSON，通过 `RunContext` 传递。迁移期原推理逻辑通过 `context.settings` 视图读取当前上下文；它使用 ContextVar，嵌套调用和线程各自持有配置，配音导入不会临时修改其他运行的输出路径。

公开命令不要求在仓库根目录启动。子进程通过安装后的 `python -m longmu` 接收配置快照；TTS 和 H3 可来自不同虚拟环境，每个环境均需安装此包。`plan`、`doctor` 与仅合成不加载 GPU 模型。

视频缓存使用台词音轨、首尾帧、实际提示词、种子、模型标记和引擎/后端文件哈希。生成、合成和续接来源统一检查完整请求。续接来源递归核验上游镜头，字幕要点和片尾提示不进入视频请求。修改内容时明确报告过期产物，由用户选择阶段和镜头重做，不自动批量重生成。

每次运行保存配置快照及状态，文件校验负责恢复判断。同一输出目录有排他锁；进程被强制杀死时可能留下锁，需确认任务退出后人工清理。此机制是本地工作流并发保护，不是多用户任务队列。

DiffSynth 目录维持原位并进入安装包。历史脚本仅用于实验，新功能应写在 LongMu 包中。尚未提供 Web 服务、持久化任务队列、日志聚合、自动重试或GPU集群调度。

多卡视频：parallel_video.py在输出目录锁内按continue_from构建续接组件，依据真实配音帧数分配到指定GPU，每卡一个隔离CUDA_VISIBLE_DEVICES的H3子进程。同组件ID顺序执行；子进程不合成，主进程核验完成产物并按ID合成连续前缀/最终视频。parallel/manifest.json记录分配和顺序，各worker使用独占日志与原子完成记录。续接末帧提取使用独立临时文件后原子替换，避免共享祖先核验时冲突。仅为单服务器多卡调度；长续接链本身串行，不是跨服务器集群调度。
